## P1 — до беты

### Прод-хостинг (решить к неделе 8)
- **What:** выбрать и поднять продакшен: сервер + Postgres с pgvector + домен + HTTPS + вебхук ЮKassa + бэкапы БД.
- **Why:** блокирует набор беты (недели 10–12) и первый тестовый платёж — без прода ни авторов, ни денег.
- **Варианты:** РФ (Selectel/Timeweb — ближе к аудитории и ЮKassa, больше ручной настройки) vs Railway+Neon (вечер работы, зарубежный). Рабочая рекомендация: Railway/Neon для беты, переезд в РФ к открытому запуску.
- **Pros:** разблокирует бету; **Cons:** ежемесячные расходы с этого момента.
- **Context:** деплой докеризован (docker-compose.prod.yml), миграции применяются на старте сервера автоматически, env-шаблон в server/.env.example. Вебхук ЮKassa настраивается в кабинете на https://<домен>/api/billing/webhook.
- **Effort:** M · **Priority:** P1 · **Blocked by:** ничем · **Blocks:** бета, платежи.

## P2 — после беты / к лендингу

### Демо-онбординг без регистрации (vision, пара к лендингу недель 8–9)
- **What:** публичная страница «посмотрите, как Перо читает книгу»: replay заранее извлечённой образцовой рукописи (лента находок + Карта мира) без аккаунта и без живых AI-вызовов.
- **Why:** сильнейший конверсионный инструмент лендинга — магия продукта до регистрации.
- **Pros:** конверсия, ноль AI-затрат (кеш); **Cons:** нужна образцовая рукопись и поддержка replay-режима в онбординге.
- **Context:** онбординг P0.4 строится с лентой находок через поллинг `world-build-status`; replay = тот же UI, источник — записанный JSON вместо живых джоб.
- **Effort:** S–M · **Priority:** P2 · **Depends on:** P0.4 готов.

### Worker джоб: отдельный процесс + параллелизм
- **What:** вынести воркер из процесса API (server/src/jobs/worker.ts) в отдельный процесс, параллелизм 2–4 джобы, graceful shutdown.
- **Why:** сейчас «официант сам готовит»: тяжёлые извлечения соревнуются с HTTP-запросами; при росте импортов очередь встанет.
- **Pros:** изоляция нагрузки, масштаб; **Cons:** второй процесс в деплое, чуть сложнее локальный запуск.
- **Context:** джобы в Postgres (`jobs`), поллинг каждые 5с; для беты 20–30 авторов текущей схемы достаточно — делать по сигналу «импорты ждут в очереди >2 мин».
- **Effort:** M · **Priority:** P2 (после беты).
