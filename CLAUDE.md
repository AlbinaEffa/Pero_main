## Что это

«Перо» — писательская студия с ИИ для русскоязычных авторов (Author.Today, Litnet).
Цель — продакшен. Монорепо: фронтенд в корне (React 19 + Vite + Tiptap + Tailwind),
бэкенд в `server/` (Express + PostgreSQL + pgvector + Drizzle).

## Модель «Мир» (UI/механика — решено 16.06.2026)

«Библия истории» переименована в **«Мир»**. **Терминология (решено 20.06.2026, гибрид):**
основной термин везде — «Мир» (UI И ответы ИИ); «библия истории» — только как индустриальный
синоним для узнаваемости: подзаголовок в шапке «Мира» («— твоя библия истории») и одно пояснение
в системном промпте. ИИ-промпты (ai.ts, extraction.ts: проверка консистентности, системная
инструкция, `buildStoryBibleContext` заголовок «=== МИР ===») вычищены от «Библии истории» —
раньше модель повторяла фразу в нестыковках («не указан в Библии истории»). Теперь говорит «нет
в Мире». Промпты прямо инструктируют модель НЕ использовать «библия истории» в выводе.
Ядро продукта — один цикл:
**пиши → Перо читает рукопись → подтверди находки (Новое) → Перо ловит нестыковки.**
Чтение **полуавтоматическое**: при изменённой/новой главе в шапке «Мира» горит
«Прочитать» (один клик; квота под контролем). ИИ здесь — **аналитик-библиотекарь,
а не генератор текста** (генерация прозы из продукта убрана).

### Объекты «Мира» (фундамент, из `story_entities`/`entity_links`/`entity_events`)
- **Сущности** 4 типов: **Персонажи** (терракота), **Локации** (шалфей),
  **Предметы/артефакты** (охра), **Правила мира** (чернильно-синий). Поля: имя,
  описание, **значимость** (Главные/Второстепенные/Эпизодические), «впервые: гл.N»,
  атрибуты-профиль (мотивация/речь/секреты и т.д.), статус (Новое → в Мире).
- **Связи** (entity_links), **События/арки** (entity_events, типы Конфликт/Отношения/
  Перемена/Открытие/Событие), **Находки** (Новое), **Правки** (Было→Стало), **Нестыковки**.
- **POV / «от чьего лица»** (18.06.2026): местоимения НИКОГДА не сущности (`isMetaEntity`
  отсеивает я/мы/ты/он/она/они…). У главы — рассказчик `chapters.pov_character` (поле `pov`
  в ответе извлечения + `sanitizePov` в lib/extraction.ts; хранится в worker.ts и bible.ts).
  «Я» в мультиперспективной книге = POV-персонаж главы, а не общая сущность «Я» (иначе черты
  разных рассказчиков слились бы в франкенштейна и сломали детектор нестыковок). Грань POV —
  лента «Кто рассказывает» в линзе «Присутствие». Бэкфилл: `server/src/scripts/backfillPov.ts`.
- **Дедуп имён-вариантов** (18.06.2026): один герой под разными именами (Риз/Ризанд,
  склонения, алиасы) — `POST /bible/:projectId/merge` в режиме `{ids}` сливает варианты
  в одну запись, имена/алиасы слитых → в `attributes.aliases` выжившего (извлечение
  дальше узнаёт их). Детектор-подсказка `findDuplicateGroups` (StoryBiblePanel,
  консервативный: тип + префикс/корень/алиас) → банд «Возможно, это один объект» в Каталоге.
  Авто-дедуп на входе: резолвер в `processExtractionResults` сопоставляет извлечённое имя
  и с каноническими именами, и с алиасами (двухпроходно) — извлечённый «Ризанд» резолвится
  в «Риз» и обогащает его, а не плодит новый pending-дубль (`aliasesOf`).

### «Мир» = набор интерактивных линз над теми же объектами (НЕ плоский список)
Конкуренты (World Anvil/Campfire/VVD) рисуют виды руками. Наш **ров**: линзы строятся
**сами из прозы**, **кликабельны обратно в текст** (узел/точка → сцена) и **подсвечивают
нестыковки прямо на виде**. Линзы:
- **Присутствие** (сетка сущность×глава — кто в какой главе, темп) — v1 флагман.
- **Связи** (граф) — v1.
- **Таймлайн**, **Арки** — v2.
- **Карта** (локации в пространстве) — позже (нужен слой координат).
- **Каталог** (карточки) — правка/одобрение, одна из линз.

### Нативный экран (UI-каркас — решено 16.06.2026)
Принцип: **текст — комната (дом), всё остальное вызывается.** Три слоя:
1. **Холст текста** — минимум хрома, пишешь/диктуешь.
2. **Пульс мира** — тонкий рельс справа, **всегда виден**: статус чтения (точка
   зелёная «прочитано» / янтарная «Прочитать»), Находки (✦ N), Нестыковки (⚠ N),
   ниже — вход «Мир» (лончер линз) и «Перо» (чат). Это состояние, на которое глянул,
   а не кнопки-загадки. Рельс = только мир (настройки/экспорт в шапке).
3. **Линзы по требованию** — **оверлей** (наезжает справа поверх текста; Esc/клик вне →
   закрыть, текст снова дом). Вызов: клик в рельсе · **⌘K / «/»** (намерение словом:
   «связи», «кто в главе», «новое», «спроси Перо») · контекст (выделил имя → «Показать
   в Мире / Где встречается»). Клик по узлу/строке линзы → прыжок в текст.

**Единый слот оверлеев (консистентность, 19.06.2026):** ВСЕ вызываемые в редакторе
экраны рендерятся в ОДНОМ `<aside>` (Editor.tsx) с общей геометрией — «Мир»/линзы,
«Справочник», «Ревизия», «Статистика», «Синхронизация» И профиль сущности
(`EntityDetailPanel`). Профиль открывается кликом по карточке в спутнике «Перо»
(`onOpenEntity` → `setDetailEntity`), переиспользует блоки `entityDisplay` в размере
`size="md"`, тело — в 2 колонки (без прокрутки). Новые вызываемые экраны добавлять
в этот же `<aside>`, а НЕ отдельными `fixed`-модалками — разнобой размеров запрещён.

Рабочий процесс: **пиши → глянул на пульс → по требованию загляни (инбокс/линза/контекст)
→ вернись к письму.** Низ сворачивается до Диктовки + тихий счётчик слов. Фокус = скрыть
рельс и низ. 8 кнопок-загадок схлопываются: статус/новые/нестыковки → пульс; Мир/
Справочник/Ревизия/Статистика/Перо → по требованию (рельс/команда/контекст). План — в
`REORG_PLAN.md` (Фаза 4).

## Ключевые архитектурные решения

### AI-провайдеры (12.06.2026)
- Все AI-вызовы ТОЛЬКО через `server/src/lib/aiProvider.ts` (`getAIProvider()` /
  `getEmbeddingProvider()`). НЕ импортировать SDK провайдеров напрямую в маршрутах.
- Провайдеры: gemini (default) | openai (любой OpenAI-совместимый через AI_BASE_URL:
  OpenRouter, DeepSeek, локальные) | anthropic. Конфиг — env, см. `server/.env.example`.
- Эмбеддинги зафиксированы на 768 измерений (pgvector `vector(768)`):
  Gemini text-embedding-004 или OpenAI text-embedding-3-small (dimensions=768).
  У Anthropic эмбеддингов нет — нужен дополнительный ключ Gemini/OpenAI.
- Обёртка вызовов: `guardChat`/`guardEmbed` из `server/src/lib/aiGuard.ts`
  (timeout + circuit breaker + лог стоимости в `cost_logs`).
- Русский-пин (18.06): во всех промптах извлечения/чата/нестыковок — строка «отвечай
  ИСКЛЮЧИТЕЛЬНО на русском». Срезала китайский вывод Kimi со 100% до ~8% утечки.
- Локальные модели оценены (19.06, Ollama :11434): gemma2:9b даёт валидный JSON и
  полностью убирает китайский, НО извлекает только персонажей (теряет локации/предметы/
  правила) и медленный (60–97с/глава). Решение: **остаёмся на Kimi (moonshot-v1-32k) +
  русский-пин** — облако даёт полные 4 типа сущностей и быстрее. Локальный профиль лежит
  закомментированным в `server/.env`; прогон качества — `server/src/scripts/testLocal.ts
  <chapterId> <model>`. Запасной кандидат при возврате к локали — qwen2.5:14b (сильнее в
  структурном JSON). Сетевой нюанс при скачивании моделей: Cloudflare WARP ломает IPv6/DNS
  к R2-CDN — на время `ollama pull` его надо отключать.

### Квоты AI (12.06.2026)
- `server/src/lib/quota.ts`: дневная квота интерактивных AI-действий per-user,
  считается из `cost_logs` (отдельных счётчиков нет). Free 20 / Pro 300 в день
  (env: QUOTA_FREE_AI_PER_DAY / QUOTA_PRO_AI_PER_DAY), сброс в полночь UTC.
- Middleware `aiQuota` стоит на всех интерактивных AI-маршрутах (ai.ts, bible.ts,
  revision.ts) ПОСЛЕ authenticateToken и rateLimit. Возвращает 429 + code AI_QUOTA_EXCEEDED.
- НЕ считаются: фоновые джобы (`worker:%`) и эмбеддинги — извлечение библии при
  импорте рукописи это aha-момент онбординга, его квотой не душим.
- План пользователя: `users.plan` ('free'|'pro') + `users.plan_expires_at`
  (миграция `server/drizzle/0013_user_plan.sql`). Эндпоинт `GET /api/ai/quota`.
- Фронтенд: `src/hooks/useAiQuota.ts`, индикатор остатка в CoauthorPanel,
  обработка 429 в useAiChat и InlineBubbleMenu.

### Биллинг ЮKassa (12.06.2026, код готов — нужны ключи и тест)
- `server/src/lib/yookassa.ts` — минимальный клиент API v3 (без SDK).
- `server/src/routes/billing.ts`: POST /checkout (создать платёж 599₽/30дн →
  confirmationUrl), POST /webhook (payment.succeeded → plan='pro', срок

### Глубокие профили персонажей (12.06.2026, бенчмарк Mythril)
- Расширенные атрибуты character в `story_entities.attributes` (jsonb, без миграции):
  background, motivations, speech, secrets, plotRelevance — поверх старых
  aliases/appearance/personality/role. Извлекаются AI, промпты в bible.ts.
- Связи: таблица `entity_links` (source→target + relation, «мать», «владеет»);
  события арки: `entity_events` (title/description/eventType по главам) —
  миграция `0015_entity_links_events.sql`. Извлекаются в том же AI-вызове
  (`relations` и `events` в JSON-ответе), дедуп по нормализованным ключам.
- Принцип одобрения сохранён: новые сущности → pending inbox; изменения описаний →
  update suggestions с diff. Атрибуты/significance одобренных сущностей обогащаются
  ТОЛЬКО аддитивно (mergeMissingAttributes — пустые поля заполняются, ничего не
  перезаписывается). Links/events авторитет не требуют, но удаляемы
  (DELETE /api/bible/links/:id, /events/:id).
- Ручная правка: PATCH /api/bible/:entityId (name/description/significance/attributes) —
  авторская правка перезаписывает. UI: режим редактирования в StoryBible.tsx.
- GET /api/bible/:projectId теперь возвращает { entities, links, events }.
- UI: группировка по significance (Главные/Второстепенные/Эпизодические),
  «Впервые: глава N», блоки «Связи» (кликабельные переходы) и «Таймлайн»
  (типизированные иконки). Общие компоненты: `src/components/editor/entityDisplay.tsx`
  (используют и StoryBiblePanel, и страница StoryBible).
- AI-контекст (`buildStoryBibleContext` в ai.ts) включает speech/motivations/secrets
  персонажей и блок СВЯЗИ — для чата и проверки консистентности.
- В /extract проверка владельца проекта теперь ДО вызова AI (не жжём токены).

### Типы глав (19.06.2026)
- Типы (колонка `chapters.chapter_type`, миграция `0021_chapter_type.sql`, без enum-ограничения
  в БД — просто text): сюжет/структура — `chapter` `prologue` `epilogue` `part` `interlude`;
  СЛУЖЕБНЫЕ (не сюжет) — `acknowledgments` `dedication` `foreword` `afterword`. Подписывается
  своим словом (Пролог/Эпилог/Часть/Благодарности…), НЕ «Глава N».
- **Единый реестр** `CHAPTER_TYPES` в `chapterDisplay.ts` (type/label/service) — ОДИН источник
  для меню создания, переключателя, импорт-детекта, подписей. `isServiceChapterType()` — хелпер.
  Бэкенд дублирует список в allowed-проверках (нет общего пакета).
- **Служебные вне ИИ-анализа**: импорт (import.ts) НЕ ставит extraction/embedding-джобы
  служебным главам; спутник «Перо» для служебной главы показывает «Служебный раздел —
  не анализируется» вместо «Прочитать» (`isServiceChapter` проп WorldCompanion).
- Хранение: POST `/projects/:id/chapters` (создание) и PATCH `/chapters/:id` принимают
  `chapterType`; GET/список отдают его (select всей строки). Фронт-тип `Chapter.chapterType`.
- Отображение: `getChapterDisplayLabel` (сайдбар) и `splitChapterTitle` (заголовок редактора,
  Editor.tsx) тип-аварны — оба снимают ведущее слово-тип из подзаголовка, чтобы не было
  «Пролог · Пролог». Лейблы — `CHAPTER_TYPE_LABELS` в `chapterDisplay.ts`.
- Смена типа: меню «+» в сайдбаре создаёт НОВУЮ главу типа; переключатель в заголовке
  редактора (клик по «Глава N»/«Эпилог» → дропдаун, EditorCanvas + `handleChapterTypeChange`
  в Editor.tsx) меняет тип СУЩЕСТВУЮЩЕЙ главы. При смене авто-заголовок «Глава N» ↔ слово-тип
  чистится автоматически (PATCH `chapterType` + `title`).
- Импорт: `classifyImportChapter` (import.ts) при вставке детектит Пролог/Эпилог/Интерлюдия
  из заголовка И чистит мусор оглавления (2+ прогона «Глава N» в title → сбрасывается в
  «Глава N» по порядку; многострочные title — берётся первая строка). Защита от того, что
  EPUB затаскивает TOC в заголовок первой главы.

### Сноски (19.06.2026)
- `FootnoteExtension.ts` — инлайновый atom-узел `footnote` {id, content}; содержимое в самом
  узле, номер НЕ хранится — считается по порядку ProseMirror-плагином (decoration
  `data-fn-number`) и рисуется CSS `.footnote-ref::after`, поэтому всегда актуален.
- Рендерится как `<span class="footnote-ref">`, НЕ `<sup>`: марка Superscript ловит любой
  `<sup>` и съедала бы сноску при загрузке (parseHTML марки приоритетнее даже с priority).
  Надстрочность даёт CSS. Чтение уже сохранённых сносок: parseHTML (`span[data-footnote-id]`,
  плюс legacy `sup[...]`) восстанавливает узел, content сохраняется, номера пересчитываются —
  round-trip проверен (вставка → save → reload → сноска на месте с текстом и номером).
- UI «как в Word» (НЕ всплывашка): маркер в тексте + **область сносок внизу главы**
  (EditorCanvas, под `EditorContent`) — список «номер + редактируемый textarea». Вставка
  (кнопка «¹»/слэш) → маркер + курсор уходит вниз к новому полю (`pendingFocusFootnoteId`).
  Клик по маркеру → прыжок к полю внизу; номер в списке → прыжок к маркеру; наведение на
  маркер → нативная подсказка (decoration `title`). Список = отражение узлов (пересчёт на
  `editor.on('transaction')`), правка поля → `updateFootnote`. Команды `updateFootnote`/
  `removeFootnote`. Стиль маркера — `.footnote-ref` в index.css.
- **Сквозная нумерация по книге**: плагин держит `offset` (meta через `footnoteNumberKey`),
  команда `setFootnoteOffset`. Editor.tsx считает offset = число сносок (`data-footnote-id`)
  во всех главах с меньшим `order` и ставит его при смене главы — номера не сбрасываются.
- **Экспорт** (server/src/routes/export.ts): `processFootnotes(html, startNum)` со сквозным
  счётчиком заменяет `sup|span[data-footnote-id]` на `[N]` и собирает «Примечания» списком внизу
  каждой главы. Подключено в markdown/txt/docx (счётчик общий по книге).
- Маркер в тексте — `[N]` в фиолетовом чипе (`.footnote-ref::before/::after` = `[`/`N]`),
  чтобы читалось как кликабельная сноска. Обзор всех сносок книги — **линза «Сноски»** в «Мире»
  (`FootnotesLens`): список «глава → [N] текст», сквозная нумерация, клик → переход в главу
  к маркеру (`bookFootnotes` парсится из контента глав в Editor.tsx, `handleJumpToFootnote`).

### Комментарии vs спутник: убран конфликт за правую сторону (21.06.2026)

### Комментарии: марки-сироты + самолечение (21.06.2026)
Симптом: клик по подсвеченному комментарию не открывал карточку. Причина — **марка-сирота**:
`data-comment-id` в контенте главы есть, а строки в `comments` нет (осталось после ручной чистки
фикстуры — удалили строки, но марки в той главе не стрипнули). Клик ищет `comments.find(id)` → null →
молчал. Фикс: (1) почистил сироту в БД; (2) **самолечение** — клик по марке без строки в БД теперь
`removeCommentById(id)` + forceSave (мёртвая подсветка снимается). В нормальном потоке сирот нет
(resolve/delete снимают марку), это страховка от внешних правок БД. Проверено: клик по валидному
комментарию открывает карточку и показывает тело.

## Design System
Always read DESIGN.md before making any visual or UI decisions.
All font choices, colors, spacing, and aesthetic direction are defined there.
Do not deviate without explicit user approval.
In QA mode, flag any code that doesn't match DESIGN.md.
Ключевое: палитра «пигментов» (никаких чистых Tailwind-цветов на пергаменте),
кириллица обязательна для любых шрифтов, motion — minimal-functional.
